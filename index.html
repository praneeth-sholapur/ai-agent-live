How I work

Six rules, learned the expensive way

RULE 01

Quarantine, never quietly drop

Bad rows get isolated with a documented reason. In the taxi build that was 2,906 rows, every one explained. Silent drops are how dashboards start lying.

RULE 02

Reconcile the counts

Rows in must equal rows accepted plus rows quarantined. 9.55M in, fully accounted for out. If the arithmetic does not close, the run does not ship.

RULE 03

Measure, don't claim

Gold layer faster? Prove it: 0.008 seconds vs 0.043 on raw, same question, identical answers. Benchmarks over adjectives, every time.

RULE 04

Test before you ship

27 automated tests and linting in CI guard the taxi pipeline. Tests are not a phase at the end. They are how you sleep after a deploy.

RULE 05

Fingerprint everything

Every source file gets a SHA-256 fingerprint and every run lands in an audit store, so any number can be traced back to the exact file it came from.

RULE 06

Never claim unearned cloud

Everything in my repo is built, tested, and reproducible by anyone. I would rather show one honest project than list ten tools I opened once.

A day in my work

How I actually work, in my own words

My day starts by checking overnight pipelines for failures, data quality issues or delays. Then a quick stand-up on work, blockers and priorities. Most of my time goes into writing Python and SQL, building and improving ETL pipelines in Azure Data Factory and Databricks, troubleshooting, optimising queries, and making data accurate and available for downstream teams. I work with engineers and business teams on requirements, review code, test changes, help with deployments, and end the day rechecking pipelines and updating tasks.

I like to understand the problem first, check requirements and data sources before coding. Python and SQL are my go-to tools, PySpark and Databricks for larger datasets, Azure Data Factory and Airflow for orchestration. When something breaks, I check logs, reproduce it, check data at each stage, narrow it to the root cause, and fix the real issue, not a temporary patch. With messy data, I profile for nulls, duplicates, inconsistent formats and schema changes, clean and validate in Python or SQL, and add quality checks so it does not happen again. Simple, reusable code, tested, and blockers flagged early.

Outside work, I follow new AI updates, play Call of Duty, and play chess.
